# 企业域环境部署指引

> 目标：把服务部署在企业内网，**员工用 AD 域账号登录**，其他电脑浏览器访问 `http://服务器IP:8000` 即可使用。

---

## 一、整体架构

```
                    ┌───────────── 域控 DC（AD / OpenLDAP）─────────────┐
                    │  ldap://dc01.corp.local:389                       │
                    └───────────────────────┬──────────────────────────┘
                                            │ ①域账号密码校验（bind）
                                            │ ②读显示名 + 所属组
┌───────────────── 应用服务器 ───────────────┴──────────────────────────┐
│  Docker Compose（docker-compose.prod.yml）                            │
│                                                                       │
│   nginx:8000  ──→  backend:8080  ──→  mysql / redis / chroma          │
│                          │                                            │
│                          └──→  Ollama（同机 或 独立 GPU 机器）         │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ 只开放 8000
              ┌─────────────────┼─────────────────┐
            员工A             员工B             员工C
        浏览器打开 http://服务器IP:8000，用域账号登录
```

**关键点：**

- 只对外暴露 **8000**（前端）。MySQL / Redis / Chroma 一律绑 `127.0.0.1`，局域网访问不到。
- 域控只做**密码校验**和**组信息读取**，本系统不保存任何域密码。
- 内置的 `admin / engineer / viewer` 本地账号**保留**，作为域控故障时的应急入口。

## 二、域控侧要先准备的（找域管理员）

### 1. 两个安全组

| 组名（示例） | 对应角色 | 权限 |
| --- | --- | --- |
| `OpsAI-Admins` | admin | 全部，含知识审核、**自愈执行** |
| `OpsAI-Engineers` | engineer | 诊断、录知识、自愈巡检 |
| （都不属于） | viewer | 只能提问 |

> 建议专门为这个系统建组，**不要把"域用户"这类大组配进来**，否则全公司都能进。

### 2. 一个只读服务账号

`CN=svc-opsai,OU=Service,DC=corp,DC=local`，只需要**读取用户属性**的权限。

> 为什么需要：AD 里普通域用户通常能读自己的属性，但读 `memberOf`、跨 OU 的条目经常受限。
> 实测中不配服务账号会出现「登录成功但角色永远是默认值」。

### 3. 确认三件事

- 域控地址：`ldap://dc01.corp.local:389` 还是 `ldaps://...:636`
- Base DN：形如 `DC=corp,DC=local`
- 用户属性：AD 是 `sAMAccountName`，OpenLDAP 通常是 `uid`

## 三、部署步骤

### 1. 准备配置

```bash
cd opsai
cp .env.example .env
```

编辑 `.env`：

```ini
MYSQL_ROOT_PASSWORD=换成强密码

SPRING_PROFILES_ACTIVE=domain
OPSAI_LDAP_URL=ldap://dc01.corp.local:389
OPSAI_LDAP_BASE_DN=DC=corp,DC=local
OPSAI_LDAP_USER_FILTER=(sAMAccountName={0})
OPSAI_LDAP_MANAGER_DN=CN=svc-opsai,OU=Service,DC=corp,DC=local
LDAP_MANAGER_PASSWORD=服务账号密码
OPSAI_LDAP_ADMIN_GROUP=CN=OpsAI-Admins
OPSAI_LDAP_ENGINEER_GROUP=CN=OpsAI-Engineers
OPSAI_LDAP_DEFAULT_ROLE=viewer
```

### 2. 启动

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

### 3. 放行防火墙（Windows 服务器）

```powershell
New-NetFirewallRule -DisplayName "OpsAI Web" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

Linux（firewalld）：

```bash
firewall-cmd --permanent --add-port=8000/tcp && firewall-cmd --reload
```

### 4. 访问

浏览器打开 `http://服务器IP:8000`，用域账号登录。

## 四、绑定方式怎么选

配置项 `bind-mode` 决定"拿什么身份去域控验证密码"：

| 值 | 绑定的身份 | 适用 | 需要服务账号 |
| --- | --- | --- | --- |
| `UPN` | `zhangsan@corp.local` | **AD 首选**，最省事 | 不需要 |
| `DN` | 按 `user-dn-pattern` 拼，如 `uid={0},ou=People,dc=corp,dc=local` | OpenLDAP 常用 | 不需要 |
| `SEARCH` | 先用服务账号搜出 DN 再绑定 | 目录结构复杂时 | 需要 |

对应配置：

```yaml
# AD
opsai.ldap.bind-mode: UPN
opsai.ldap.upn-suffix: corp.local

# OpenLDAP
opsai.ldap.bind-mode: DN
opsai.ldap.user-dn-pattern: uid={0},ou=People,dc=corp,dc=local
```

## 五、验证清单

部署完按这个顺序验一遍：

| # | 检查项 | 期望 |
| --- | --- | --- |
| 1 | `docker compose ps` | 5 个容器都是 Up / healthy |
| 2 | 浏览器打开 `http://服务器IP:8000` | 登录页出现"企业域环境"提示 |
| 3 | 用**普通域账号**登录 | 成功，进入极简问答页 |
| 4 | 用**OpsAI-Engineers 组**的账号登录 | 成功，进管理台 |
| 5 | 用**OpsAI-Admins 组**的账号登录 | 成功，能进"自愈中心"并看到"确认执行"按钮 |
| 6 | 输错域密码 | 提示"域账号或密码错误" |
| 7 | 用 `admin / admin123` 登录 | 仍能进（应急入口） |

```bash

  -H "Content-Type: application/json" \
  -d '{"username":"zhangsan","password":"你的域密码"}'
```

返回里 `"authSource":"LDAP"` 就说明走的是域认证。

## 六、常见问题（都是实测踩过的）

### 1. `[LDAP: error code 32 - No Such Object]`

两个原因，按顺序排查：

- **搜索基准写错了**：DN 被重复拼接，形如 `ou=People,dc=corp,dc=local,dc=corp,dc=local`。
  本项目已修（不让 `LdapContextSource` 设 base），如果自己改代码，注意别在连接源上 `setBase()`。
- **匿名访问被拒**：AD 和 OpenLDAP 默认**不允许匿名查询**。必须配 `manager-dn`，
  或者确认绑定的用户本身有读权限。

### 2. `[LDAP: error code 49 - Invalid Credentials]`

- 密码真的错了，或
- `bind-mode=DN` 时 `user-dn-pattern` 拼出来的 DN 不存在（用 `ldapsearch` 手工确认一下 DN）

### 3. 能登录，但角色永远是 `viewer`

说明**组信息没读到**。检查：

```bash
# 用服务账号确认能读到 memberOf
ldapsearch -x -H ldap://dc01.corp.local \
  -D "CN=svc-opsai,OU=Service,DC=corp,DC=local" -w '密码' \
  -b "DC=corp,DC=local" "(sAMAccountName=zhangsan)" memberOf
```

读不到 → 服务账号权限不够；读到了但角色还不对 → `admin-group` / `engineer-group` 的**匹配片段**写错了
（只要 `memberOf` 的值里**包含**这段文字就算命中，不需要写完整 DN）。

### 4. 域控挂了会不会整个系统瘫痪

不会。域控不可达时：

- 域账号登录 → 提示"域认证服务暂时不可用"
- **本地账号（admin/engineer/viewer）仍然可以登录**

### 5. 日志在哪

```bash
docker compose -f docker-compose.prod.yml logs -f backend | grep LDAP
```

排查认证问题时，把 `application-domain.yml` 里的
`org.springframework.ldap` 日志级别调到 `DEBUG`，能看到完整的 LDAP 交互。

## 七、并发能力（决定买什么显卡）

这是**唯一需要按人数规划硬件**的地方，代码和架构都不用改：

| 硬件 | 可并发 | 说明 |
| --- | --- | --- |
| RTX 4050 6GB | **1** | 其他人排队，每人等 20~40 秒 |
| RTX 4090 / A10 24GB | 4~6 | 建议设 `OLLAMA_NUM_PARALLEL=4` |
| 多卡 / 多机 + 负载均衡 | 10+ | 需要额外加 nginx upstream |

GPU 机器上设置：

```powershell
# 允许局域网访问 Ollama（只有独立 GPU 机器才需要）
setx OLLAMA_HOST "0.0.0.0:11434" /M

# 并发数
setx OLLAMA_NUM_PARALLEL "4" /M
```

> ⚠️ 如果 Ollama 和应用在同一台机器，**不要**设 `OLLAMA_HOST=0.0.0.0`，
> 让它继续只听 127.0.0.1，后端通过 `host.docker.internal` 访问即可，更安全。

## 八、安全建议

1. **只开放 8000**，不要给数据库和 Ollama 开外网端口
2. **改掉内置账号的默认密码**（`admin123` 等），或者用完就禁用
3. 域控自签证书时，`ldaps://` 可以设 `OPSAI_LDAP_TRUST_ALL_CERTS=true` 跳过校验 ——
   **只在内网这么用**，公网环境必须导入正式证书
4. 定期看"操作日志"页，域账号的登录、提问、自愈执行都有记录可追溯
5. 自愈的"执行处置动作"只有 admin 能做，接口层也有 403 拦截

## 九、数据都在哪 + 备份到备份机器

### 所有数据都在这台服务器上

部署完以后，**业务数据全部集中在一台专用服务器**，用户电脑上不存任何数据：

| 数据 | 存在哪 | 说明 |
| --- | --- | --- |
| 知识库 / 故障单 / 诊断记录 | MySQL 容器卷 `mysql-data` | 容器的 docker volume，重建不丢 |
| 用户与操作日志 | 同上 | 域账号首次登录自动建档也在这里 |
| 上传的日志、截图 | 宿主机 `opsai/data/` | 绑定挂载，容器重建不丢（已实测） |
| 向量索引 | 后端 JVM 内存 | 启动时从 MySQL 的 kb_chunk 加载 |
| 模型文件 | GPU 机器的 Ollama 目录 | 不在本项目里 |
| 备份 | 本机 `opsai/backups/` + **备份机器** | 见下 |

### 两个角色看到的界面（同一个网址）

所有人在自己电脑浏览器打开 `http://服务器IP:8000`，**用各自的域账号登录**，
系统按角色自动分流：

| 角色 | 判定方式 | 登录后看到 |
| --- | --- | --- |
| 普通员工 | 不属于任何授权组（默认 viewer） | **极简问答页**：一个输入框 + 截图 + 追问，看不到任何数据 |
| 运维人员 | 属于 `OpsAI-Engineers` | 完整管理台：诊断 / 知识库 / 案例 / 统计 / **操作日志** |
| 管理员 | 属于 `OpsAI-Admins` | 上面全部 + 知识审核 + **自愈执行** |

界面差异是**前端按角色渲染 + 后端接口层 403 双重保证**的，
普通员工即使手工敲 `/logs` 地址也进不去，直接调接口同样被拒。

### 备份到备份机器

主服务器上所有数据只在这一台机器 —— **这台坏了就是全丢**，所以备份必须离开本机。

```powershell
# 每天备份并复制到备份机器
powershell -File scripts\backup.ps1 -RemotePath "\\BACKUP-PC\opsai-backups"

# 共享需要账号时
powershell -File scripts\backup.ps1 -RemotePath "\\192.168.1.50\backup\opsai" 
          -RemoteUser "backup" -RemotePassword "密码"
```

脚本做的事：

1. `mysqldump` 导出全库（知识库、故障单、诊断记录、用户、日志）
2. 打包 `opsai/data/` 里的上传文件
3. 压成一个 zip（含 `BACKUP-INFO.txt` 记录时间/主机/Git 版本）
4. **复制到备份机器**的共享目录
5. 清理本机 14 天前、备份机 30 天前的旧备份

**设置每天自动跑**（任务计划程序）：

```powershell
$action  = New-ScheduledTaskAction -Execute "powershell.exe" `
            -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\opsai\scripts\backup.ps1" -RemotePath "\\BACKUP-PC\opsai-backups"'
$trigger = New-ScheduledTaskTrigger -Daily -At 2am
Register-ScheduledTask -TaskName "OpsAI 每日备份" -Action $action -Trigger $trigger -RunLevel Highest
```

### 恢复

```powershell
docker compose down
# 解压备份到临时目录，得到 mysql-opsai.sql 和 data/
docker compose up -d mysql
docker cp mysql-opsai.sql opsai-mysql:/tmp/
docker exec opsai-mysql sh -c "mysql -uroot -p你的密码 --default-character-set=utf8mb4 opsai < /tmp/mysql-opsai.sql"
# 把 data/ 覆盖回项目根目录
docker compose up -d
```

恢复后建议验证：登录 admin → 看知识库条数对不对 → 随便问一个问题确认能检索到资料。

## 十、多台机器怎么分工（数据一份，推理多台）

### 先说不建议的做法

**不要每台机器都跑一整套 `docker compose`**：

```
机器A: 后端 + MySQL + 数据①
机器B: 后端 + MySQL + 数据②      ← 三份数据各自独立
机器C: 后端 + MySQL + 数据③
```

用户连到哪台就只能看到哪台的数据 —— 知识库、故障单、日志全部分裂，
和你想要的"数据共享"正好相反。而且每份都要单独备份，运维成本翻三倍。

### 推荐：数据一份 + 推理多台

```
              ┌────── 应用服务器（唯一的数据所在地）──────┐
              │  nginx:8000  →  backend  →  MySQL / 上传  │
              │                    │                      │
              │                    └→ nginx:11434 ──┬─────┼──→ GPU机A  Ollama
              └───────────────────────────────────  ┘     ├──→ GPU机B  Ollama
                       ↑                                   └──→ GPU机C  Ollama
                 用户只访问这个
              http://应用服务器IP:8000

              ┌────── 备份机器 ──────┐
              │ 共享目录，只存备份     │
              └──────────────────────┘
```

**为什么这样分工才对：**

| 资源 | 瓶颈在哪 | 怎么扩 |
| --- | --- | --- |
| 数据（MySQL / 上传 / 日志） | 不在并发上 | **只放一份**，加机器不会让它变快，只会让数据分裂 |
| 模型推理（Ollama） | **真正的瓶颈**（一次生成 20~40 秒） | 加 GPU 机器 |
| Web 后端（Spring Boot） | 几乎不是瓶颈 | 单实例足够几百个用户点页面 |

所以：**后端只开一台，GPU 机器按人数加。**

### 加 GPU 机器的步骤

1. 新机器装 Ollama，pull 同样的两个模型：
   ```bash
   ollama pull qwen2.5:7b-instruct-q4_K_M
   ollama pull bge-m3
   ```
2. 允许内网访问（**只对自己的网段**）：
   ```powershell
   setx OLLAMA_HOST "0.0.0.0:11434" /M
   setx OLLAMA_NUM_PARALLEL "4" /M
   ```
   然后防火墙只放行 nginx 那台机器：
   ```powershell
   New-NetFirewallRule -DisplayName "Ollama from LB" -Direction Inbound -Protocol TCP `
     -LocalPort 11434 -RemoteAddress 192.168.1.10 -Action Allow
   ```
3. 在 nginx 上加一行（配置见 [nginx/ollama-lb.conf](nginx/ollama-lb.conf)）：
   ```nginx
   upstream ollama_cluster {
       least_conn;
       server 192.168.1.101:11434 max_fails=2 fail_timeout=30s;
       server 192.168.1.102:11434 max_fails=2 fail_timeout=30s;   # ← 新增一台就加一行
       keepalive 32;
   }
   ```
4. 应用服务器 `.env` 指到负载均衡器：
   ```ini
   OPSAI_OLLAMA_BASE_URL=http://192.168.1.10:11434
   ```

**关键配置项**（`ollama-lb.conf` 里已经写好）：
`proxy_buffering off` —— 不关的话 nginx 会把流式输出攒着，
首字延迟会从 200ms 变成好几秒，体验直接崩掉。

### 备份机器

独立于上面所有机器，只需要一个共享目录（NAS / SMB / 另一台 Windows 的共享文件夹），
**不需要装 Docker**。

```powershell
powershell -File scripts\backup.ps1 -RemotePath "\\BACKUP-PC\opsai-backups"
```

### 什么情况下才需要多台后端

只有当**单台后端扛不住 Web 请求**时才需要（几百人同时在线点页面才可能发生，
模型推理早就先撑不住了）。那时才需要：

- `opsai.auth.store=redis` —— 会话共享，否则用户会被负载均衡踢掉线
- MySQL / 上传目录换成共享存储
- 前面再加一层 nginx 做后端负载均衡

**现阶段不用考虑这些**，单后端 + 多 GPU 机就是最省事又能扩展的方案。

## 十二、域管控下 IT 侧要配合做的事

这一节是**域管理员 / 网络管理员**要做的，系统本身不用改。
做完之后用户端是"零安装、零配置"的。

### 1. 加一条 DNS 别名

在域 DNS 里给应用服务器加 A 记录（或 CNAME）：

```
opsai.corp.local   →   192.168.1.10
```

好处：服务器以后换 IP，用户端不用改任何东西。

验证：在任意域内电脑 `ping opsai.corp.local` 能通。

### 2. 用组策略下发入口（免安装）

**方式 A：桌面快捷方式**

`用户配置 → 首选项 → Windows 设置 → 快捷方式`

- 名称：`运维排障助手`
- 目标类型：URL
- 目标 URL：`http://opsai.corp.local:8000`
- 位置：`桌面`

**方式 B：浏览器主页**

`用户配置 → 管理模板 → Windows 组件 → Internet Explorer → 主页`

> 两种都不需要在电脑上装任何东西，用户登录域后就能用。

### 3. 用企业 CA 签证书配 HTTPS（建议）

内网也不该用裸 HTTP 传登录密码。

**第一步**：向企业 CA 申请服务器证书（证书模板选"Web 服务器"），
主题名填 `opsai.corp.local`。

**第二步**：放到项目里，改 `opsai-web/nginx.conf`：

```nginx
server {
    listen 443 ssl;
    server_name opsai.corp.local;

    ssl_certificate     /etc/nginx/certs/opsai.crt;
    ssl_certificate_key /etc/nginx/certs/opsai.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 其余 location 配置与 80 端口完全一致
    location / { root /usr/share/nginx/html; index index.html; try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://backend:8080/api/; proxy_buffering off; proxy_read_timeout 300s; }
}
```

**第三步**：`docker-compose.prod.yml` 里把证书目录挂进去、暴露 443：

```yaml
  web:
    ports:
      - "8000:80"
      - "443:443"
    volumes:
      - ./certs:/etc/nginx/certs:ro
```

域内电脑本来就信任企业 CA，**不会有证书告警**。

**第四步（可选）**：LDAP 也换成加密的

```ini
OPSAI_LDAP_URL=ldaps://dc01.corp.local:636
```

域控用自签证书时再设 `OPSAI_LDAP_TRUST_ALL_CERTS=true`；有正式 CA 证书就不用设。

### 4. 用组策略下发防火墙规则（可选）

如果不想在服务器上手工加防火墙规则，改用 GPO：

`计算机配置 → Windows 设置 → 安全设置 → 高级安全 Windows Defender 防火墙 → 入站规则 → 新建规则`

- 类型：端口 → TCP → 特定本地端口 `8000`（和 443）
- 操作：允许
- 应用到：持有该服务器计算机账号的 OU
